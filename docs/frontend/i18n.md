# Internationalisation

Six languages, one catalog per language, no ambient state.

## Where things live

```
shared/config/i18n/
  locales.ts          the registry: code, html tag, og locale, dir, native name
  messages/*.json     one catalog per language — copy is data, not code
  messages/index.ts   derives MessageKey from en.json; types every other file as Catalog
  translate.ts        translate(locale, key, params)
  path.ts             localizedPath / splitLocalePath / canonicalLocaleRedirect
  locale-context.tsx  LocaleProvider, useLocale, useT
  require-locale.ts   requireLocale — the loader guard
  index.ts            the slice's public API
```

Nothing outside that directory imports a catalog module directly.

## Using it

**In a component**, take a bound translator from context:

```tsx
const t = useT()
t('nav.browse')
t('browse.searchTitle', { query })
```

**In a `loader` or `meta`**, there is no React context — pass the locale
explicitly:

```ts
export function loader({ params }: Route.LoaderArgs) {
  const locale = requireLocale(params.locale)
  // …
}

export function meta({ loaderData, params }: Route.MetaArgs) {
  if (!loaderData) return errorMeta(params.locale)
  const { locale } = loaderData
  return pageMeta({ title: translate(locale, 'docs.title') /* … */ })
}
```

Two rules that are easy to get wrong:

- **A loader must return its `locale`** (and the `origin`), because `meta` reads
  loader data, not context.
- **A `meta` must guard `loaderData`.** Every localized loader can throw —
  `requireLocale` rejects a bad first segment, a detail loader rejects an
  unknown id — and React Router still calls `meta` with no loader data. An
  unguarded destructure turns a clean 404 into a render crash.

**For links**, use `LocaleLink` / `LocaleNavLink` from `shared/ui/locale-link`,
or `useLocalePath()` for a `<Form action>` or a programmatic `navigate`. The
switcher additionally records the choice in the `dsh_locale` cookie, so a later
bare-URL visit is forwarded to the reader's prefix with a 302. A plain
`<Link to="/browse">` on a Japanese page navigates to the English one — the
reader's language ends at the first click, and a crawler following the same link
finds a Japanese page whose every outbound link leaves the Japanese cluster.

## No ambient locale

There is no module-level "current locale". One Worker isolate serves many
requests concurrently, so ambient locale state would let one reader's language
appear in another reader's response. The locale travels two ways only: through
React context (for components) and as an explicit argument (everywhere else).

## Adding a message

1. Add the key to `messages/en.json`. `MessageKey` is derived from that file, so the other nine catalogs stop type-checking until they declare it too.
2. Add it to all nine other `messages/<code>.json` files.
3. Placeholders are `{name}`. The parity test asserts that every catalog
   declares exactly the placeholders its English source does — a dropped
   `{count}` renders a sentence that silently states nothing, and an invented
   one renders literal braces to a reader.

`pnpm run test` fails on a missing key, an extra key, a blank value, or a
placeholder mismatch, in any language.

## Adding a language

1. Add an entry to `LOCALES` in `locales.ts`.
2. Add `messages/<code>.json` with the same keys as `en.json`.
3. Import it in `messages/index.ts` and assign it as `Catalog`.
4. Register it in `CATALOGS` in `translate.ts`.

Nothing else has a list of languages in it. Routes, `hreflang`, the sitemap,
`og:locale:alternate` and the header switcher all read the registry.

For a right-to-left language, set `dir: 'rtl'`; the document element already
applies it. Expect a styling pass — the layout has never been exercised in RTL.

## What is _not_ translated

**Most catalog metadata.** An artifact's `displayName` and `keywords` remain
exactly as the author published them. README Markdown and the short `summary`
are the exceptions: plugin admission schedules a machine translation of both
for every locale. The versioned stock backfill also schedules every README and
summary that predates the current model policy immediately after deployment.
The detail loader asks `GetArtifactDetail` for its route locale and renders
generated README/summary prose whenever that body is still on the row: the
current completed translation, or the previous completed body retained while a
replacement is pending or failed. A locale with no generated body yet still
renders the untouched source. Generated
README prose is visibly labelled with `artifact.readmeMachineTranslated`.
Summaries follow the same retain-until-replaced rule in both the detail DTO and listing
queries; a one-line translated summary carries no label, the same convention
app stores use for localized descriptions.

The checked-in catalogs still translate the frame: the title pattern, type
name, breadcrumb trail, install warnings and `inLanguage` on structured data.
The runtime Agent target list is passed from `LOCALE_CODES`, so URL locales,
message catalogs, `hreflang` and README translations cannot drift into separate
language sets.

Runtime catalog prose is translated by `hy-mt2-1.8b` in LM Studio on the Mac
mini. The Worker reaches it through a private Workers VPC Service and
Cloudflare Tunnel. Four durable Agent shards match LM Studio's four parallel
slots; each README is split into resumable 4,000-character prose chunks while
fenced code bypasses the model. The current policy version is part of every
source digest, so changing the model, prompt or chunk semantics must bump that
version and restart the stock backfill.

**Code identifiers.** The snippets on `/docs` stay in English: a JSON key is an
identifier, and an identifier that changes with the reader's language is a
broken instruction. Product names — `dsh`, `DeepSeek Harness`, `MCP`,
`SKILL.md` — stay as written for the same reason.

**Long-form product docs.** Button labels and chrome (`docs.menu`,
`docs.search.*`, `docs.nav.*`, `docs.onThisPage`, scoring table labels) stay in
these catalogs. Guide prose lives in `frontend/content/docs/*.mdx`. English is
the source, and every public guide has a physical MDX file for all six locales
(`index.zh-CN.mdx`, …). English fallback prevents a broken route if a file is
temporarily absent, but that fallback locale is excluded from canonical,
`hreflang`, and sitemap output until the translation exists. The exception is scoped in
[`../decisions/adr-0005-product-docs-with-fumadocs.md`](../decisions/adr-0005-product-docs-with-fumadocs.md).
Code identifiers stay English in every locale. Docs pages embed short
per-section demo clips instead of one long video per page: eleven clips
(`quickstart-launch/-model/-workspace/-task`, `hub-search/-browse/-artifact/
-install`, `develop-write/-observe/-loop`), each rendered for all six locales
under `frontend/public/docs/video/` (English unsuffixed, other locales
suffixed, e.g. `quickstart-launch.zh-CN.mp4`, with matching `-poster.jpg`
stills), produced by the Remotion project in `.workspace/promo-video`.
On-screen copy matches the page locale; the caption and transcript are
localized as well.

**Long-form blog.** Series names, empty-state copy, and the byline label
(`blog.*`, `nav.blog`, `feed.blog.*`, `seo.blog.description`) stay in these
catalogs. Post prose lives in `frontend/content/blog/{series}/*.mdx`. English
is the source, and every public post has a physical MDX file for all six
locales. English fallback prevents a broken route; that fallback locale is
excluded from canonical, `hreflang`, and sitemap output until the
translation exists. The exception is scoped in
[`../decisions/adr-0007-editorial-blog.md`](../decisions/adr-0007-editorial-blog.md).
Code identifiers stay English in every locale. Dates are formatted with
`Intl.DateTimeFormat` and the locale registry's `tag`, not with catalog
templates.

## The backend sends keys, not prose

The catalog stays language-neutral in the database because the backend emits
message _keys_ (`artifactKind.bundle.label`, `install.warning.buildAllowance`),
never sentences. `i18n.test.ts` enumerates the emittable keys from the backend's
own domain modules rather than restating them, so a newly added kind, category
or install warning fails the test instead of rendering a raw key to a user.
