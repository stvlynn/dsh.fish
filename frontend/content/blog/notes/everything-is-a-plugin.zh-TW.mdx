想像一下：你在常用的程式碼編輯器裡裝了一個擴充功能，結果它悄悄把終端機弄壞了，或者竄改了你的模型設定。當你試圖排查原因時，卻發現編輯器本身是一個巨大的黑盒子，所有擴充功能都像是用膠帶硬貼在外殼上的補丁。

現在換一種思路：如果這個應用的核心幾乎是空的呢？如果聊天視窗、Bash 工具、模型連線，甚至驅動智慧體思考的迴圈本身，全都採用與第三方擴充功能完全相同的方式載入，會發生什麼？

這正是 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（`dsh`）在 README 開篇寫下那句 **everything is a plugin（一切皆外掛）** 時的真實含義。這句話不是為了外掛市場造勢的口號，而是由底層組合執行期 [Cordis](https://github.com/cordiverse/cordis)（詳見論文 [_A Programming Paradigm for Spatiotemporal Composability_](https://arxiv.org/abs/2608.25512)）支撐的架構法則。

一旦看懂這條法則在磁碟上是如何運作的，DeepSeek Harness 與本目錄站（`dsh.fish`）的設計邏輯就會瞬間清晰起來。下面我們從你電腦上的一個資料夾出發，一步步拆解到一個正在執行的智慧體工作階段。

![Profile 把目錄 artifact 組合成一個受權限範圍約束的 Harness 工作階段。](/blog/diagrams/plugin-composition.svg)

## A profile is the unit that boots

在討論「外掛」之前，先看看當你在終端機輸入 `npx @deepseek-ai/dsh web` 時，機器上究竟發生了什麼。

智慧體把資料存放在哪裡？預設情況下，DeepSeek Harness 會在 `~/.dsh`（或環境變數 `$DSH_HOME` 指定的路徑）建立一個主目錄，裡面有一個名為 `profiles/` 的子資料夾。

你可以把一個 **Profile（設定檔集）**（`$DSH_HOME/profiles/<name>`）理解成一份「智慧體配方」。它存放著一組 npm 套件與設定修補檔（`cordis.patch.yml`），決定了行程啟動時有哪些工具、哪些模型介面卡、以及什麼樣的介面。

當你啟動 `dsh` 時，你永遠是在啟動某一個具體的 Profile：

- `dsh web` 啟動的是 `web` Profile（在 `http://127.0.0.1:3080` 開啟瀏覽器介面）。
- `dsh --profile headless` 啟動的是無介面的一次性命令列執行器。
- `dsh --profile sdk` 和 `dsh --profile acp` 啟動的是供 Python/TypeScript SDK 或外部自動化工具呼叫的協定服務。

系統裡沒有任何「繞過 Profile 直接載入內建全家桶」的暗門。既然所有入口都透過 Profile 啟動，你自然不可能抽象地「把外掛裝進 DeepSeek Harness」——不指定目標 Profile 的安裝，就像把寄件地址寫成空白一樣無處落腳。

## 四種積木：從最輕量的說明文件到完整技術堆疊

如果說 Profile 是啟動時的「總配方」，那麼你可以往裡面放哪些食材？

瀏覽 `dsh.fish` 時你會發現，全站只有四種元件類型（Kind）。這不是我們為了分類發明的標籤，而是 DeepSeek Harness 原生支援載入的四種入口：

| 類型（Kind）         | 適合什麼場景？                                      | DeepSeek Harness 如何載入它？                                                                 |
| ------------ | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| **Skill（技能）**        | 用純 Markdown 教會模型一套可重用的操作流程           | 保存在 `$DSH_HOME/skills/<name>/SKILL.md`，模型在需要時按需讀取                |
| **Agent preset（預設）** | 定義專屬的角色人設、提示詞前後綴與工具組合   | 透過 `agent.cordis.yml` 宣告（在新版 Harness 中同樣作為 Bundle 分發）        |
| **Bundle（擴充包）**       | 用程式碼新增工具、UI 面板、模型介面卡或執行期鉤子 | 在 `package.json` 中宣告 `dsh.bundle` 的 npm 套件，透過 `dsh plugin add` 安裝進 Profile            |
| **Profile（設定堆疊）**      | 把整套搭配好的 Bundle 清單一鍵分享給團隊      | 在 `@deepseek-ai/dsh-base` 之上按順序疊加的一組 Bundle（`dsh.profile.bundles`）  |

細心的讀者可能會問：為什麼沒有 `mcp-server` 或 `hook-bridge`？早期我們曾嘗試把這兩者列為獨立類型，但很快用 `301` 重新導向把他們合併回了 `/browse`。原因很簡單：Harness 執行期根本沒有叫做這兩個名字的獨立載入槽位——MCP 服務和鉤子本身就是裝在 Bundle 或 Profile 裡面的。如果目錄站去宣傳執行期無法直接載入的虛擬分類，只會讓一般使用者在安裝時一頭霧水。

## 為什麼「安裝計畫」比一行盲目執行的腳本更安全？

在很多工具生態裡，安裝外掛意味著複製一行指令按下 Enter，然後祈禱它別弄亂環境。正因為 DeepSeek Harness 的 Profile 是分層組裝出來的，我們在 `dsh.fish` 上採用了完全透明的做法：**先看計畫，再改環境**。

無論你是在網頁端查看外掛、在終端機執行 `npx @dsh-fish/cli`，還是在工作階段裡透過 `@dsh-fish/hub` 外掛搜尋，你拿到的都是同一份**安裝計畫（Install Plan）**。

在實際使用中，你只需要記住這三行指令：

```bash
npx @dsh-fish/cli show <artifact-id>
npx @dsh-fish/cli add <artifact-id> --profile web
dsh --profile web
```

為什麼要把 `show`（查看計畫）和 `add`（執行安裝）拆開？因為第三方外掛程式碼擁有與你目前系統使用者相同的權限。如果一個來自 Git 儲存庫的套件要求執行建置腳本（build script），這段腳本是在智慧體沙箱之外執行的。安裝計畫會提前把這件事攤在陽光下：除非你明確加上 `--allow-build-scripts` 確認放行，否則它絕不會在背景悄悄執行建置程式碼。

## 既然「一切皆外掛」，核心還負責什麼？

讀到這裡，你可能會產生一個疑問：如果工具、模型和介面全都是外掛，那整個系統靠什麼保證不散架？

即便在「一切皆外掛」的架構裡，仍有四條底線貫穿每一個工作階段：

1. **工作階段日誌僅追加且單行程上鎖。** 每一次提問、工具呼叫和回答都會寫入持久化的事件流（`session.v4.jsonl.zstd`），並由 `SessionHandle` 單行程鎖保護，避免兩個行程同時寫壞同一段歷史。
2. **工作區（Workspace）是你明確交出的目錄。** 智慧體預設只會在你選定的專案資料夾內工作；在選定工作區之前，Web 介面的輸入框甚至不會解鎖。
3. **權限由具名預設嚴格分檔。** 新工作階段預設以 `workspace-write` 啟動。未經你確認，或者你沒有主動切到 `danger-full-access`，外掛工具都必須遵守目前權限檔位。
4. **API 金鑰永遠留在本機。** 你的模型金鑰保存在 `$DSH_HOME/.credentials.yaml` 或環境變數裡，`dsh.fish` 既不接觸金鑰，也不中轉任何模型請求。

## 執行期與目錄站的明確分工

把這層邊界理順之後，兩個工具的角色就一目了然了：

- **DeepSeek Harness（`dsh`）** 是負責透過 Cordis 組裝外掛並執行智慧體的引擎，其官方文件位於 [deepseek-harness.github.io](https://deepseek-harness.github.io/deepseek-harness/)。
- **`dsh.fish`** 是圍繞這四類可載入積木建立的公共目錄與安裝計畫解析器。我們的[產品文件](/docs)專門講解如何發佈這四類元件，以及透明的品質與維護度評分是如何計算的。

下次當你在本站看到任何一個外掛時，不妨先問自己一個問題：*它準備修改我哪個 Profile 裡的哪一層配方？* 當你開始用「配方與圖層」而不是「黑盒擴充功能」來思考時，你就真正掌握了 DeepSeek Harness 的精髓。
