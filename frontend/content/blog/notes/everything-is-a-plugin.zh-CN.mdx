想象一下：你在常用的代码编辑器里装了一个扩展，结果它悄悄把终端搞崩了，或者篡改了你的模型配置。当你试图排查原因时，却发现编辑器本身是一个巨大的黑盒，所有扩展都像是用胶带硬贴在外壳上的补丁。

现在换一种思路：如果这个应用的核心几乎是空的呢？如果聊天窗口、Bash 工具、模型连接，甚至驱动智能体思考的循环本身，全都采用与第三方扩展完全相同的方式加载，会发生什么？

这正是 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（`dsh`）在 README 开篇写下那句 **everything is a plugin（一切皆插件）** 时的真实含义。这句话不是为了插件市场造势的口号，而是由底层组合运行时 [Cordis](https://github.com/cordiverse/cordis)（详见论文 [_A Programming Paradigm for Spatiotemporal Composability_](https://arxiv.org/abs/2608.25512)）支撑的架构法则。

一旦看懂这条法则在磁盘上是如何运作的，DeepSeek Harness 与本目录站（`dsh.fish`）的设计逻辑就会瞬间清晰起来。下面我们从你电脑上的一个文件夹出发，一步步拆解到一个正在运行的智能体会话。

![Profile 把目录 artifact 组合成一个受权限范围约束的 Harness 会话。](/blog/diagrams/plugin-composition.svg)

## A profile is the unit that boots

在讨论“插件”之前，先看看当你在终端输入 `npx @deepseek-ai/dsh web` 时，机器上究竟发生了什么。

智能体把数据存放在哪里？默认情况下，DeepSeek Harness 会在 `~/.dsh`（或环境变量 `$DSH_HOME` 指定的路径）创建一个主目录，里面有一个名为 `profiles/` 的子文件夹。

你可以把一个 **Profile（配置文件集）**（`$DSH_HOME/profiles/<name>`）理解成一份“智能体配方”。它存放着一组 npm 包和配置补丁文件（`cordis.patch.yml`），决定了进程启动时有哪些工具、哪些模型适配器、以及什么样的界面。

当你启动 `dsh` 时，你永远是在启动某一个具体的 Profile：

- `dsh web` 启动的是 `web` Profile（在 `http://127.0.0.1:3080` 打开浏览器界面）。
- `dsh --profile headless` 启动的是无界面的一次性命令行执行器。
- `dsh --profile sdk` 和 `dsh --profile acp` 启动的是供 Python/TypeScript SDK 或外部自动化工具调用的协议服务。

系统里没有任何“绕过 Profile 直接加载内置全家桶”的暗门。既然所有入口都通过 Profile 启动，你自然不可能抽象地“把插件装进 DeepSeek Harness”——不指定目标 Profile 的安装，就像把寄件地址写成空白一样无处落脚。

## 四种积木：从最轻量的说明文档到完整技术栈

如果说 Profile 是启动时的“总配方”，那么你可以往里面放哪些食材？

浏览 `dsh.fish` 时你会发现，全站只有四种组件类型（Kind）。这不是我们为了分类发明的标签，而是 DeepSeek Harness 原生支持加载的四种入口：

| 类型（Kind）         | 适合什么场景？                                      | DeepSeek Harness 如何加载它？                                                                 |
| ------------ | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| **Skill（技能）**        | 用纯 Markdown 教会模型一套可复用的操作流程           | 保存在 `$DSH_HOME/skills/<name>/SKILL.md`，模型在需要时按需读取                |
| **Agent preset（预设）** | 定义专属的角色人设、提示词前后缀与工具组合   | 通过 `agent.cordis.yml` 声明（在新版 Harness 中同样作为 Bundle 分发）        |
| **Bundle（扩展包）**       | 用代码新增工具、UI 面板、模型适配器或运行时钩子 | 在 `package.json` 中声明 `dsh.bundle` 的 npm 包，通过 `dsh plugin add` 安装进 Profile            |
| **Profile（配置栈）**      | 把整套搭配好的 Bundle 列表一键分享给团队      | 在 `@deepseek-ai/dsh-base` 之上按顺序叠加的一组 Bundle（`dsh.profile.bundles`）  |

细心的读者可能会问：为什么没有 `mcp-server` 或 `hook-bridge`？早期我们曾尝试把这两者列为独立类型，但很快用 `301` 重定向把它们合并回了 `/browse`。原因很简单：Harness 运行时根本没有叫做这两个名字的独立加载槽位——MCP 服务和钩子本身就是装在 Bundle 或 Profile 里面的。如果目录站去宣传运行时无法直接加载的虚拟分类，只会让普通用户在安装时一头雾水。

## 为什么“安装计划”比一行盲目执行的脚本更安全？

在很多工具生态里，安装插件意味着复制一行命令回车，然后祈祷它别搞乱环境。正因为 DeepSeek Harness 的 Profile 是分层组装出来的，我们在 `dsh.fish` 上采用了完全透明的做法：**先看计划，再改环境**。

无论你是在网页端查看插件、在终端运行 `npx @dsh-fish/cli`，还是在会话里通过 `@dsh-fish/hub` 插件搜索，你拿到的都是同一份**安装计划（Install Plan）**。

在实际使用中，你只需要记住这三行命令：

```bash
npx @dsh-fish/cli show <artifact-id>
npx @dsh-fish/cli add <artifact-id> --profile web
dsh --profile web
```

为什么要把 `show`（查看计划）和 `add`（执行安装）拆开？因为第三方插件代码拥有与你当前系统用户相同的权限。如果一个来自 Git 仓库的包要求运行构建脚本（build script），这段脚本是在智能体沙箱之外执行的。安装计划会提前把这件事摆在台面上：除非你显式加上 `--allow-build-scripts` 确认放行，否则它绝不会在后台悄悄执行构建代码。

## 既然“一切皆插件”，核心还负责什么？

读到这里，你可能会产生一个疑问：如果工具、模型和界面全都是插件，那整个系统靠什么保证不散架？

即便在“一切皆插件”的架构里，仍有四条底线贯穿每一个会话：

1. **会话日志仅追加且单进程加锁。** 每一次提问、工具调用和回答都会写入持久化的事件流（`session.v4.jsonl.zstd`），并由 `SessionHandle` 单进程锁保护，避免两个进程同时写坏同一段历史。
2. **工作区（Workspace）是你显式交出的目录。** 智能体默认只在你选定的项目文件夹内工作；在选定工作区之前，Web 界面的输入框甚至不会解锁。
3. **权限由具名预设严格分档。** 新会话默认以 `workspace-write` 启动。未经你确认，或者你没有主动切到 `danger-full-access`，插件工具都必须遵守当前权限档位。
4. **API 密钥永远留在本地。** 你的模型密钥保存在 `$DSH_HOME/.credentials.yaml` 或环境变量里，`dsh.fish` 既不接触密钥，也不中转任何模型请求。

## 运行时与目录站的明确分工

把这层边界理顺之后，两个工具的角色就一目了然了：

- **DeepSeek Harness（`dsh`）** 是负责通过 Cordis 组装插件并运行智能体的引擎，其官方文档位于 [deepseek-harness.github.io](https://deepseek-harness.github.io/deepseek-harness/)。
- **`dsh.fish`** 是围绕这四类可加载积木建立的公共目录与安装计划解析器。我们的[产品文档](/docs)专门讲解如何发布这四类组件，以及透明的质量与维护度评分是如何计算的。

下次当你在本站看到任何一个插件时，不妨先问自己一个问题：*它准备修改我哪个 Profile 里的哪一层配方？* 当你开始用“配方与图层”而不是“黑盒扩展”来思考时，你就真正掌握了 DeepSeek Harness 的精髓。
