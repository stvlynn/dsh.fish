你是否遇到过这样的糟心体验：照着网页文档的步骤去装一个插件，结果发现命令行工具的参数完全对不上；或者让 AI 智能体去读网站的 `/llms.txt`，读出来的却是三周前早就过期的旧说明？

一旦一个开发者中心同时服务于“浏览器里的人类读者”和“终端里的智能体”，**多端信息不一致（Split-Brain）**就会成为最常见的故障源：文档表格里硬编码的评分权重和后端接口对不上，已经废弃的插件分类还挂在侧边栏里，或者会话内插件的安装行为和网页端存在细微偏差。

截至 2026 年 8 月 29 日，我们在 `dsh.fish` 上交付的所有功能都围绕着一条工程铁律展开：**无论是人类网页、CLI 客户端、会话内插件还是 AI 智能体，所有入口都必须读取同一份唯一真实数据源（Single Source of Truth）。** 下面带你一步步看清这次架构升级如何改变你的日常使用体验。

## 产品文档告别单页标签卡，升级为六语言指南树

在最初的版本里，`/docs` 只是一个带分类标签页的单页 React 组件。当目录只需要两百字简介时这样就够了；但一旦用户需要一步步学习如何发布扩展包、如何使用 CLI、或者想搞清楚质量评分到底是怎么算出来的，单页结构就彻底捉襟见肘了。

因此，我们将产品文档重构为基于 Fumadocs 的独立文档区，在构建期编译并完整覆盖全部六种语言（`en`、`zh-CN`、`zh-TW`、`ja`、`ko`、`ru`）：

- **按任务组织的完整指南：** 涵盖快速上手（Quickstart）、核心概念、四种发布格式的专门教程、命令行工具（`@dsh-fish/cli`）、会话内插件（`@dsh-fish/hub`）、提交流程、评分机制与 REST API。
- **实时拉取的评分权重表：** 文档中的评分表不再粘贴容易过期的静态数字，而是直接调用 `GET /api/v1/scoring` 实时渲染。
- **独立的文档搜索路由：** 文档搜索运行在 `/docs/search`，将 `/api/*` 命名空间完全留给 Hono 后端接口。

## 不离开对话窗口直接安装插件：`@dsh-fish/hub` 上架 npm

在浏览器里逛目录适合发现新工具，但当你已经沉浸在一个 DeepSeek Harness 会话中时，切出去复制安装命令往往会打断思路。

8 月份，我们将 **`@dsh-fish/hub`** 正式发布到了 npm。它是一个原生的 Cordis 插件，可以直接加载到正在运行的 Harness 会话里：

1. **会话内搜索与一键安装：** 提供 `hub_search`、`hub_show`、`hub_install`、`hub_remove`、`hub_update` 等工具与浏览卡片，在会话内直接查看 README 并执行与网站端完全一致的安装计划。
2. **修复设备授权登录（Device Grant）闭环：** 修复了浏览器端点击 `Authorize` 后的令牌兑换竞态问题，让插件和 CLI 轮询的 `$DSH_HOME/.dsh-fish-token.json` 能够稳定落盘。
3. **接入原生插件设置中心：** 通过 Harness 的插件设置客户端注册配置，并采用 npm 11 可信发布（Trusted Publishing）保障供应链安全。

## 砍掉“目录幻觉”：为什么要让两个组件类型退役？

当我们把目录分类与 DeepSeek Harness 实际能加载的入口逐一核对时，发现早期的两个分类名——`mcp-server` 与 `hook-bridge`——其实属于“目录自己发明的概念”。

Harness 运行时并没有这两个名字的独立加载槽位；无论是 MCP 服务还是钩子，本质上都是封装在 **Bundle（扩展包）** 或 **Profile（配置栈）** 里的。保留运行时根本无法直接安装的分类，只会误导用户。

因此我们精简了分类体系，并配置了 `301` 永久重定向：

- 原有的 `/kind/mcp-server` 和 `/kind/hook-bridge` 自动 `301` 跳转至 `/browse`。
- 旧发布指南自动跳转至 `/docs/plugins`。
- 目录只保留 Harness 真正加载的**四种类型**：`bundle`、`skill`、`agent-preset`、`profile`，并将功能分类与 [awesome-dsh-plugin.com](https://awesome-dsh-plugin.com) 对齐。

## 把 AI 智能体当作一等公民用户（`llms.txt` 与 Markdown 内容协商）

当一个 AI 智能体访问技术网站时，如果服务器返回一堆夹杂着导航栏脚本的 HTML 外壳，不仅浪费 Token，还会干扰模型的提取准确度。

智能体或自动化脚本现在可以直接使用以下接口：

- **全景索引地图：** 根目录 `/llms.txt`、文档区 `/docs/llms.txt`（以及单文件全文拼接版 `/docs/llms-full.txt`）、博客区 `/blog/llms.txt` 与 `/blog/feed.xml`（Atom 订阅源）。
- **原生 Markdown 内容协商：** 在任意文档或博客路径后加上 `.md`（如 `/docs/cli.md`、`/blog/index.md`），或在请求头中带上 `Accept: text/markdown`。即便访问了不存在的 404 路径，只要带有 `Accept: text/markdown`，系统也会返回一份精简的 Markdown 恢复导航图，而不是庞大的前端应用外壳。
- **无闪烁的多语言 README 更新：** 当插件更新 README 触发后台重译时，系统会一直保留上一版已完成的翻译，直到新译文生成完毕，彻底消除了切换语言时的空白闪烁。

## 我该选择哪个入口？

根据你手头正在做的事，选择最顺手的入口即可：

- **想了解发布规范或评分细则：** 直接浏览 [`/docs`](/docs) 产品文档。
- **想把文档喂给自己的 AI 智能体：** 让它读取 `/docs/llms.txt` 或 `/blog/llms.txt`。
- **习惯在终端里干净利落地管理配置：** 运行 `npx @dsh-fish/cli show <id>` 与 `npx @dsh-fish/cli add <id> --profile web`。
- **正在 DeepSeek Harness 会话里写代码：** 安装并启用 `@dsh-fish/hub`。
