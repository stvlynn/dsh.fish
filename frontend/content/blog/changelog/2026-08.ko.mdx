문서 페이지를 보고 패키지 설치 명령어를 따라 쳤는데 CLI 옵션이 다르거나, AI 에이전트에게 사이트의 `/llms.txt`를 읽혔더니 3주 전의 낡은 설명을 기준으로 코드를 작성한 적이 있으신가요?

개발자 허브가 브라우저의 사람 독자와 터미널의 자율 에이전트를 동시에 지원하기 시작하면, **표면마다 정보가 따로 노는 현상(Split-Brain)**이 가장 흔한 장애 원인이 됩니다. 문서 표에 적어 둔 점수 가중치가 실제 백엔드 API와 달라지거나, 이미 사라진 플러그인 분류가 사이드바에 남거나, 세션 내부 플러그인의 설치 동작이 웹 화면과 미묘하게 달라지는 식입니다.

2026년 8월 29일까지 `dsh.fish`에 배포된 모든 기능은 단 하나의 엔지니어링 원칙을 중심으로 설계되었습니다. **웹 브라우저, CLI 클라이언트, 세션 내 플러그인, 그리고 AI 에이전트까지 모든 진입점이 단 하나의 단일 진실 공급원(Single Source of Truth)을 읽어야 한다**는 원칙입니다.

![공유 소스에서 사람, 설치 클라이언트, 웹, agent용 표면으로 카탈로그가 전달되는 흐름.](/blog/diagrams/hub-surfaces.svg)

## 단일 탭 페이지에서 6개 국어 가이드 트리로 진화한 제품 문서

초기의 `/docs`는 아티팩트 종류별 탭만 있는 단일 React 페이지였습니다. 간단한 요약만 보여줄 때는 충분했지만, 번들 배포 방법이나 CLI 사용법, 품질 점수 계산 방식을 차근차근 설명하기에는 턱없이 부족했습니다.

그래서 `/docs`를 빌드 시점에 컴파일되는 Fumadocs 섹션으로 전면 재구축하고 6개 언어(`en`, `zh-CN`, `zh-TW`, `ja`, `ko`, `ru`)를 모두 지원하도록 만들었습니다.

- **작업 중심의 가이드 구성:** 빠른 시작(Quickstart), 핵심 개념, 네 가지 배포 형식별 가이드, CLI(`@dsh-fish/cli`), 세션 내 허브 플러그인(`@dsh-fish/hub`), 제출 절차, 점수 체계, REST API를 각각의 독립된 문서로 제공합니다.
- **실시간으로 불러오는 점수 가중치 표:** 문서 안에 숫자를 하드코딩하는 대신 `GET /api/v1/scoring`을 직접 호출해 항상 실제 백엔드 가중치와 일치하도록 만들었습니다.
- **전용 문서 검색 경로:** 문서 검색은 `/docs/search`에서 작동하며, `/api/*` 경로는 Hono 백엔드 전용으로 깔끔하게 분리했습니다.

## 세션을 떠나지 않고 바로 설치하는 `@dsh-fish/hub`

새 플러그인을 둘러볼 때는 웹 브라우저가 편하지만, 이미 DeepSeek Harness 세션을 띄워 놓고 작업 중일 때는 창을 바꿔 명령어를 복사하는 과정이 흐름을 끊습니다.

8월에 npm으로 정식 배포된 **`@dsh-fish/hub`**는 실행 중인 Harness 세션 안에 바로 로드할 수 있는 Cordis 플러그인입니다.

1. **세션 내부 검색·조회·설치:** `hub_search`, `hub_show`, `hub_install`, `hub_remove`, `hub_update` 도구를 통해 README를 읽고 웹사이트와 완전히 동일한 설치 계획을 세션 안에서 즉시 적용합니다.
2. **기기 인가(Device Grant) 로그인 완결:** 브라우저에서 `Authorize`를 눌렀을 때 플러그인이나 CLI가 폴링 중인 토큰(`$DSH_HOME/.dsh-fish-token.json`)이 정확히 교환되도록 경합 조건을 수정했습니다.
3. **네이티브 설정 연동 및 npm 11 신뢰 배포:** Harness의 플러그인 설정 클라이언트를 통해 설정을 등록하며, npm 11 Trusted Publishing을 적용했습니다.

## '카탈로그의 허구' 덜어내기: 두 가지 종류를 퇴역시켰던 이유

초기 분류 체계를 DeepSeek Harness의 실제 부팅 구조와 대조해 본 결과, `mcp-server`와 `hook-bridge`라는 두 종류를 걷어냈습니다.

Harness 런타임에는 그런 이름의 독립된 로드 슬롯이 없으며, MCP 서버나 훅은 모두 **Bundle**이나 **Profile** 안에 담겨 로드되기 때문입니다. 런타임이 직접 설치할 수 없는 분류를 남겨 두지 않기 위해 구형 URL(`/kind/mcp-server` 등)은 `/browse`로, 구형 배포 가이드는 `/docs/plugins`로 `301` 리다이렉트했습니다.

이제 카탈로그는 Harness가 실제로 로드하는 **네 가지 종류(`bundle`, `skill`, `agent-preset`, `profile`)**만 다루며, 카테고리 역시 [awesome-dsh-plugin.com](https://awesome-dsh-plugin.com)과 맞췄습니다.

에이전트나 스크립트가 바로 활용할 수 있는 엔드포인트는 다음과 같습니다.

- **발견 맵:** 루트의 `/llms.txt`, 가이드용 `/docs/llms.txt`(및 전체 합본인 `/docs/llms-full.txt`), 블로그용 `/blog/llms.txt`와 `/blog/feed.xml`(Atom 피드).
- **직접 Markdown 협상:** `/docs/cli.md`처럼 `.md` 확장자를 붙이거나 `Accept: text/markdown` 헤더를 보내면 순수 Markdown을 반환합니다. `Accept: text/markdown` 요청에서 404가 발생하더라도 앱 셸 대신 간결한 복구 안내 맵을 돌려줍니다.
- **깜빡임 없는 다국어 README 갱신:** 새 README 번역이 돌아가는 동안 이전 완료 본문을 유지해 어느 언어에서도 빈 화면이 깜빡이지 않습니다.

## 상황에 맞는 진입점 고르기

- **패키징 규격이나 점수 산정 기준을 배우고 싶을 때:** [`/docs`](/docs)를 열어 보세요.
- **코딩 에이전트에게 문서를 주고 싶을 때:** `/docs/llms.txt`나 `/blog/llms.txt`를 건네주세요.
- **터미널에서 바로 계획을 확인하고 설치하고 싶을 때:** `npx @dsh-fish/cli show <id>`와 `npx @dsh-fish/cli add <id> --profile web`을 실행하세요.
- **DeepSeek Harness 세션 안에서 작업 중일 때:** `@dsh-fish/hub`를 로드하세요.

*(웹사이트가 아니라 DeepSeek Harness 런타임 자체의 업데이트 내역이 궁금하시다면 [Harness 릴리스](/blog/harness) 시리즈와 새로 추가된 [v0.1.5~v0.2.1 마일스톤 총정리](/blog/harness/v0-1-5-to-v0-2-1) 글을 확인해 보세요.)*
