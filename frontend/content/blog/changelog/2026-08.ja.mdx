Web のドキュメント通りにコマンドを打ったのに CLI のオプションが違っていたり、AI エージェントに `/llms.txt` を読ませたら 3 週間前の古い仕様を前提にコードを書かれたりしたことはないでしょうか。

開発者向けのハブが「ブラウザで読む人間」と「ターミナルで動くエージェント」の両方を相手にし始めると、**窓口ごとの情報の食い違い（スプリットブレイン）**が最も起きやすい障害になります。ドキュメントの表に直書きされたスコア配分がいつの間にか API とズレる、廃止されたはずのプラグイン種別がサイドバーに残る、といった問題です。

2026 年 8 月 29 日までに `dsh.fish` で公開したすべての機能は、1 つの設計原則に貫かれています。それは**「Web、CLI、セッション内プラグイン、そして AI エージェントのすべてが、ただ 1 つの情報源（Single Source of Truth）を参照する」**ということです。

![共有ソースから、人向け、インストールクライアント、Web、agent 向けの各面へカタログを配信する流れ。](/blog/diagrams/hub-surfaces.svg)

## 1 枚のタブ画面から、6 言語の製品ドキュメントツリーへ

当初の `/docs` は、種類ごとのタブを切り替えるだけの 1 ページの React コンポーネントでした。しかし、公開手順や CLI の使い方、スコアの算出ロジックを段階的に学ぼうとすると、1 枚のページでは到底収まりません。

そこで `/docs` を Fumadocs による独立したドキュメントセクションへと作り直し、ビルド時に 6 言語（`en`、`zh-CN`、`zh-TW`、`ja`、`ko`、`ru`）すべてをコンパイルする構成にしました。

- **目的別のガイド構成：** クイックスタート、基本概念、4 つの公開フォーマット別の手順、CLI（`@dsh-fish/cli`）、セッション内プラグイン（`@dsh-fish/hub`）、登録申請、スコア計算、REST API をそれぞれ独立したガイドとして整備しました。
- **スコア配分のライブ取得：** ドキュメント内のスコア表は数値をベタ書きせず、`GET /api/v1/scoring` を直接呼び出して描画します。
- **検索経路の分離：** ドキュメント検索は `/docs/search` で動作し、Hono バックエンドの `/api/*` とは明確に分離されています。

## セッションを離れずに検索・導入できる `@dsh-fish/hub`

ブラウザでカタログを眺めるのは便利ですが、すでに DeepSeek Harness のセッション内で作業しているときに、わざわざブラウザに戻ってコマンドをコピーするのは手間がかかります。

そこで npm に公開したのが **`@dsh-fish/hub`** です。Cordis プラグインとして稼働中のセッションに直接読み込めます。

1. **セッション内での検索・確認・導入：** `hub_search`、`hub_show`、`hub_install`、`hub_remove`、`hub_update` を使い、README の確認からインストール計画の適用までをチャットの中で完結できます。
2. **デバイス認可（Device Grant）の確実な受け渡し：** ブラウザで `Authorize` を押した際に、プラグインや CLI がポーリングしているトークン（`$DSH_HOME/.dsh-fish-token.json`）が確実に引き換えられるよう競合状態を修正しました。
3. **プラグイン設定の統合と npm 11 Trusted Publishing：** Harness のプラグイン設定クライアントを通じて設定を登録し、npm 11 の信頼済みパブリッシングに準拠しています。

## 「カタログ上の虚構」をなくす：2 つの種類を廃止した理由

初期の分類を DeepSeek Harness の実際の読み込み機構と照らし合わせた結果、`mcp-server` と `hook-bridge` の 2 つを廃止しました。

Harness にはそのような名前の単独の読み込みスロットは存在せず、MCP サーバーやフックは Bundle や Profile の一部として読み込まれるからです。存在しないスロットをカタログに並べるのをやめ、旧 URL（`/kind/mcp-server` など）は `/browse` へ、旧ガイドは `/docs/plugins` へ `301` リダイレクトしました。

現在のカタログは、Harness が実際に読み込む **4 種類（`bundle`、`skill`、`agent-preset`、`profile`）** のみを扱い、カテゴリも [awesome-dsh-plugin.com](https://awesome-dsh-plugin.com) と揃えています。

## AI エージェントを第一級の利用者として扱う（`llms.txt` と Markdown ネゴシエーション）

AI エージェントがドキュメントを読むとき、ナビゲーション付きの巨大な HTML を返すのはトークンの無駄遣いです。

エージェントやスクリプトからは、次のエンドポイントをそのまま利用できます。

- **全体マップ：** ルートの `/llms.txt`、ガイド用の `/docs/llms.txt`（および全文結合版の `/docs/llms-full.txt`）、ブログ用の `/blog/llms.txt` と `/blog/feed.xml`（Atom）。
- **Markdown ネゴシエーション：** `/docs/cli.md` のように `.md` を付けるか、`Accept: text/markdown` ヘッダーを送ると Markdown が返ります。`Accept: text/markdown` 付きで 404 になった場合も、HTML シェルではなく簡潔なリカバリーマップを返します。
- **ちらつきのない翻訳 README：** README の再翻訳中は直前の完了済み翻訳を表示し続けるため、言語を切り替えても本文が空になる瞬間がありません。

## 場面に応じた使い分け

- **パッケージの公開方法やスコアの仕組みを知りたいとき：** [`/docs`](/docs) を開く。
- **AI エージェントに仕様を読ませたいとき：** `/docs/llms.txt` または `/blog/llms.txt` を渡す。
- **ターミナルだけで手早く確認・導入したいとき：** `npx @dsh-fish/cli show <id>` と `npx @dsh-fish/cli add <id> --profile web` を実行する。
- **DeepSeek Harness のセッション内で完結させたいとき：** `@dsh-fish/hub` を読み込む。
