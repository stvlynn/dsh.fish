你是否遇過這樣的糟心體驗：照著網頁文件的步驟去裝一個套件，結果發現命令列工具的參數完全對不上；或者讓 AI 智慧體去讀網站的 `/llms.txt`，讀出來的卻是三週前早就過期的舊說明？

一旦一個開發者中心同時服務於「瀏覽器裡的人類讀者」與「終端機裡的智慧體」，**多端資訊不一致（Split-Brain）**就會成為最常見的故障源：文件表格裡寫死的評分權重和後端介面不一致，已經廢棄的外掛分類還掛在側邊欄裡，或者工作階段內外掛的安裝行為和網頁端存在細微偏差。

截至 2026 年 8 月 29 日，我們在 `dsh.fish` 上交付的所有功能都圍繞著一條工程鐵律展開：**無論是人類網頁、CLI 客戶端、工作階段內外掛還是 AI 智慧體，所有入口都必須讀取同一份唯一真實資料源（Single Source of Truth）。** 下面帶你一步步看清這次架構升級如何改變你的日常使用體驗。

## 產品文件告別單頁分頁卡，升級為六語言指南樹

在最初的版本裡，`/docs` 只是一個帶分類分頁的單頁 React 元件。當目錄只需要兩百字簡介時這樣就夠了；但一旦使用者需要一步步學習如何發佈擴充包、如何使用 CLI、或者想搞清楚品質評分到底是怎麼算出來的，單頁結構就徹底捉襟見肘了。

因此，我們將產品文件重構為基於 Fumadocs 的獨立文件區，在建置期編譯並完整覆蓋全部六種語言（`en`、`zh-CN`、`zh-TW`、`ja`、`ko`、`ru`）：

- **按任務組織的完整指南：** 涵蓋快速上手（Quickstart）、核心概念、四種發佈格式的專門教學、命令列工具（`@dsh-fish/cli`）、工作階段內外掛（`@dsh-fish/hub`）、提交流程、評分機制與 REST API。
- **即時拉取的評分權重表：** 文件中的評分表不再貼上容易過期的靜態數字，而是直接呼叫 `GET /api/v1/scoring` 即時渲染。
- **獨立的文件搜尋路由：** 文件搜尋執行在 `/docs/search`，將 `/api/*` 命名空間完全留給 Hono 後端介面。

## 不離開對話視窗直接安裝外掛：`@dsh-fish/hub` 上架 npm

在瀏覽器裡逛目錄適合發現新工具，但當你已經沉浸在一個 DeepSeek Harness 工作階段中時，切出去複製安裝指令往往會打斷思路。

8 月份，我們將 **`@dsh-fish/hub`** 正式發佈到了 npm。它是一個原生的 Cordis 外掛，可以直接載入到正在執行的 Harness 工作階段裡：

1. **工作階段內搜尋與一鍵安裝：** 提供 `hub_search`、`hub_show`、`hub_install`、`hub_remove`、`hub_update` 等工具與瀏覽卡片，在工作階段內直接查看 README 並執行與網站端完全一致的安裝計畫。
2. **修復裝置授權登入（Device Grant）閉環：** 修復了瀏覽器端點擊 `Authorize` 後的權杖兌換競態問題，讓外掛與 CLI 輪詢的 `$DSH_HOME/.dsh-fish-token.json` 能夠穩定落盤。
3. **接入原生外掛設定中心：** 透過 Harness 的外掛設定客戶端註冊設定，並採用 npm 11 可信發佈（Trusted Publishing）保障供應鏈安全。

## 砍掉「目錄幻覺」：為什麼要讓兩個元件類型退役？

當我們把目錄分類與 DeepSeek Harness 實際能載入的入口逐一核對時，發現早期的兩個分類名——`mcp-server` 與 `hook-bridge`——其實屬於「目錄自己發明的概念」。

Harness 執行期並沒有這兩個名字的獨立載入槽位；無論是 MCP 服務還是鉤子，本質上都是封裝在 **Bundle（擴充包）** 或 **Profile（設定堆疊）** 裡的。保留執行期根本無法直接安裝的分類，只會誤導使用者。

因此我們精簡了分類體系，並設定了 `301` 永久重新導向：

- 原有的 `/kind/mcp-server` 和 `/kind/hook-bridge` 自動 `301` 跳轉至 `/browse`。
- 舊發佈指南自動跳轉至 `/docs/plugins`。
- 目錄只保留 Harness 真正載入的**四種類型**：`bundle`、`skill`、`agent-preset`、`profile`，並將功能分類與 [awesome-dsh-plugin.com](https://awesome-dsh-plugin.com) 對齊。

## 把 AI 智慧體當作一等公民使用者（`llms.txt` 與 Markdown 內容協商）

當一個 AI 智慧體造訪技術網站時，如果伺服器傳回一堆夾雜著導覽列腳本的 HTML 外殼，不僅浪費 Token，還會干擾模型的提取準確度。

現在，`dsh.fish` 上的每一個頁面都原生支援 Markdown 交付。點擊下方互動式模擬介面中的步驟 1–4，查看四個交付表面是如何保持零偏差同步的：

智慧體或自動化腳本現在可以直接使用以下介面：

- **全景索引地圖：** 根目錄 `/llms.txt`、文件區 `/docs/llms.txt`（以及單檔案全文拼接版 `/docs/llms-full.txt`）、部落格區 `/blog/llms.txt` 與 `/blog/feed.xml`（Atom 訂閱源）。
- **原生 Markdown 內容協商：** 在任意文件或部落格路徑後加上 `.md`（如 `/docs/cli.md`、`/blog/index.md`），或在請求標頭中帶上 `Accept: text/markdown`。即便造訪了不存在的 404 路徑，只要帶有 `Accept: text/markdown`，系統也會傳回一份精簡的 Markdown 恢復導覽圖，而不是龐大的前端應用外殼。
- **無閃爍的多語言 README 更新：** 當外掛更新 README 觸發背景重譯時，系統會一直保留上一版已完成的翻譯，直到新譯文產生完畢，徹底消除了切換語言時的空白閃爍。

## 我該選擇哪個入口？

根據你手頭正在做的事，選擇最順手的入口即可：

- **想了解發佈規範或評分細則：** 直接瀏覽 [`/docs`](/docs) 產品文件。
- **想把文件餵給自己的 AI 智慧體：** 讓它讀取 `/docs/llms.txt` 或 `/blog/llms.txt`。
- **習慣在終端機裡乾淨俐落地管理設定：** 執行 `npx @dsh-fish/cli show <id>` 與 `npx @dsh-fish/cli add <id> --profile web`。
- **正在 DeepSeek Harness 工作階段裡寫程式碼：** 安裝並啟用 `@dsh-fish/hub`。
