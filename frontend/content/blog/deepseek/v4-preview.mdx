When an AI model expands its context window from 128,000 tokens to **1,000,000 tokens**, the first temptation is obvious: stop worrying about what to read, dump the entire repository into the prompt, attach every screenshot, and let the model sort it out.

Then you try it in a real coding session. By turn fifteen, latency creeps up, repeated screenshots bloat your request payload, and irrelevant files drown out the three lines of code that actually caused the bug.

When DeepSeek published [DeepSeek-V4 Preview](https://www.deepseek.com/en/news/v4-preview/) on 24 April 2026, the headline number was that 1M token default window. What mattered even more for everyday users and plugin authors was what happened *next*: how DeepSeek Harness evolved its official adapter over the summer so an agent could actually use a 1M window, handle images via the Files API, and retire the legacy model strings cleanly.

## Two open-weight models, one standard 1M window

Let us start with what the April announcement actually put on the table.

Instead of selling long context as a separate, high-priced tier, DeepSeek made **1M tokens the standard window** across two open-weight Mixture-of-Experts (MoE) models powered by **token-wise compression plus DSA (DeepSeek Sparse Attention)**:

| Model | Total / Active Parameters | API `model` string | Best used for... |
| --- | --- | --- | --- |
| **DeepSeek-V4-Pro** | 1.6T total / 49B active | `deepseek-v4-pro` | Complex architecture, multi-file debugging, math, and deep reasoning (`thinking: max`) |
| **DeepSeek-V4-Flash** | 284B total / 13B active | `deepseek-v4-flash` | Fast iteration, subagent tasks, and everyday tool loops at a fraction of the cost |

Both models use the existing API `base_url` and support thinking and non-thinking modes (in the web chat and mobile app, you see these as **Expert Mode** and **Instant Mode**). For agent workloads, the announcement explicitly recommends running thinking mode at intensity `max`.

Just as important was the sunset notice: the old model names **`deepseek-chat` and `deepseek-reasoner` were scheduled to stop working on 24 July 2026 at 15:59 UTC**. Until that cutoff, they acted as temporary aliases routing to V4-Flash; after that date, they became dead strings.

## How DeepSeek Harness turned the announcement into working plumbing

A model announcement says what the weights can do. An agent runtime has to turn those capabilities into reliable tool calls.

If you trace the DeepSeek Harness releases leading up to August's `v0.1.2-alpha.1`, you can watch the official adapter build out the V4 integration step by step:

1. **Native image prompts (`v0.1.0-rc.8`):** The DeepSeek adapter gained native image request support across `/goal`, `/plan`, and `@` file or session references.
2. **Experimental vision sidecar (`v0.1.1-rc.1`):** Added `DeepSeek-V4-Flash-Vision-Exp` (`deepseek-v4-flash-vision-exp`) on the official adapter so sessions could send screenshots and diagrams as visual inputs.
3. **Files API upload reuse and auto-resize (`v0.1.1-rc.2`):** Instead of re-uploading megabytes of base64 image data on every turn, the adapter switched to the **Files API**, reusing uploaded file IDs across turns and automatically resizing or converting images to match the model's requirements.
4. **Plugin telemetry and image-aware compaction (`v0.1.2-alpha.1`):** The adapter began counting images properly during session compaction and attaching enabled plugin package names and versions to official requests.

*(Note for readers on newer builds: as covered in our [DeepSeek-V4.1-Flash follow-up](/blog/deepseek/v4-1-flash-and-search), the September 2026 `v0.1.5` release folded native vision directly into `deepseek-flash`, retiring the separate `deepseek-v4-flash-vision-exp` string while keeping `deepseek-v4-pro` (`DeepSeek-V4-Pro-0813`) as the heavy reasoning SKU.)*

## Why a 1M window changes budgeting, not the need for retrieval

Here is the trap that catches many developers when they first get a 1M context window: **having more room does not make wasted context free.**

Even when a model can hold 1,000,000 tokens without clipping:

- **Every input token still costs latency and money** on every step of an agent loop.
- **Noisy tool outputs dilute attention.** If a search tool dumps 80,000 tokens of unindexed logs into history, the model has to wade through all of it on every subsequent turn.
- **Vision has its own budget.** The Files API saves network bandwidth by reusing uploaded file handles, and auto-resize keeps pixel dimensions in check, but neither mechanism knows whether ten nearly identical browser screenshots are actually useful. Good plugins deduplicate visual evidence before returning it to the session.

## A practical migration checklist for users and plugin authors

If you maintain a plugin, skill, or profile on `dsh.fish`, run through this four-point check:

```text
Legacy string (retired)      August V4 string         Current V4.1+ string (Sept/Oct 2026)
-----------------------      ------------------       ------------------------------------
deepseek-chat             -> deepseek-v4-flash     -> deepseek-flash (text + native vision)
deepseek-reasoner         -> deepseek-v4-pro       -> deepseek-v4-pro (DeepSeek-V4-Pro-0813)
```

1. **Purge `deepseek-chat` and `deepseek-reasoner` from your READMEs and examples.** Those strings stopped resolving after 24 July 2026. On `dsh.fish`, a README that still instructs users to export dead model names is treated as a maintenance defect.
2. **Design skills around targeted evidence, not blind repo dumps.** Use the 1M window to hold architectural context and multi-file diffs across long debugging sessions, not as an excuse to skip search and filtering.
3. **Treat images as first-class tool results.** If your plugin generates plots, UI screenshots, or visual diffs, return clean, deduplicated image files so the official adapter can cache them through the Files API and account for them during compaction.
4. **Keep model selection in the user's profile.** `dsh.fish` install plans never write API keys and never hardcode a user's billing choice. Let the user's profile decide whether a task warrants `deepseek-v4-pro` or `deepseek-flash`.
