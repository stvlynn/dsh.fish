Представьте картину: вы обновляете DeepSeek Harness до [v0.1.2-alpha.1](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.2-alpha.1) (выпуск от 27 августа 2026 года, тег `dsh-v0.1.2-alpha.1`), запускаете привычный headless-скрипт автоматизации и видите абсолютно пустой терминал. Проходит десять секунд, двадцать. Вы уже тянетесь к `Ctrl+C`, решив, что процесс завис, как вдруг на экран разом выводится готовый ответ.

Ничего не зависло. В `dsh-v0.1.2-alpha.1` впервые появилась чёткая граница между **логом прогресса для человека** и **чистым результатом для скрипта**. Это одна из четырёх крупных перемен в пре-релизе, которые затронули запуск сессий, выбор моделей для субагентов и метаданные в запросах к API.

Давайте разберём по шагам, как устроены эти изменения — от команды в терминале до заголовков сетевого запроса.

![Harness v0.1.2 разделяет metadata запроса и output headless-процесса.](/blog/diagrams/harness-request-path.svg)

## Почему ваш скрипт притих: разделение `stderr` и `stdout`

Начнём с того самого «пустого терминала», потому что за ним стоит решение проблемы, знакомой каждому автору скриптов.

В ранних сборках headless-режим смешивал всё в стандартный поток вывода (`stdout`): трассировку инструментов, промежуточные шаги и финальный ответ. Если вы передавали вывод `dsh` по конвейеру в `jq` или сохраняли в файл, приходилось сначала вычищать служебный шум регулярными выражениями.

Начиная с `dsh-v0.1.2-alpha.1`, потоки разделены:

- **`stderr` (стандартный поток ошибок, дескриптор 2)** в реальном времени транслирует прогресс и вызовы инструментов.
- **`stdout` (стандартный поток вывода, дескриптор 1)** хранит тишину до конца хода и печатает **только итоговый результат**.

Теперь одна строка с перенаправлением потоков даёт и чистый файл результата, и подробный журнал выполнения:

```bash
dsh --profile <profile-name> run "your task" >result.txt 2>progress.log
```

## Субагентам больше не нужно копировать дорогую модель родителя

Когда вывод приведён в порядок, следующим узким местом в сложных задачах становятся задержка и стоимость токенов.

Раньше при запуске вспомогательного субагента (например, чтобы быстро проверить папку или сжать лог тестов) дочерний процесс автоматически наследовал модель родительской сессии. Если основной агент работал на тяжёлой рассуждающей модели, каждое мелкое поручение обходилось так же дорого и медленно.

В `v0.1.2-alpha.1` субагенты получили собственный выбор модели в пределах прав родителя:

1. **Гибкий выбор модели:** родительский агент может назначить субагенту провайдера, модель и уровень рассуждений (reasoning effort) в рамках тех учётных данных, к которым уже имеет доступ.
2. **Ограничения при запуске:** вызывающий код может задать провайдера, модель, усилие рассуждений и **максимальную длину ответа (maximum output length)**.
3. **Собственная модель для Claude Code и Codex:** субагенты Claude Code и Codex теперь берут модель из конфигурации профиля, а не клонируют слот родительской сессии.

Для авторов профилей на `dsh.fish` это означает, что в одном профиле можно сочетать мощную модель-координатора и быстрых субагентов на Flash-модели.

## Что отправляется по сети, когда включены плагины

Когда вы устанавливаете Bundle из каталога в свой профиль, видит ли провайдер модели, какие именно плагины загружены?

Начиная с `dsh-v0.1.2-alpha.1`, **официальный адаптер DeepSeek** прикрепляет к исходящим запросам **имена пакетов и версии всех включённых плагинов** активного профиля.

Важны две детали:

- **Заголовок с плагинами включён по умолчанию, но отключаем.** В корпоративных или изолированных инсталляциях его можно выключить.
- **Потоковая выгрузка логов сессии работает только по явному согласию (opt-in).** Второй канал позволяет передавать инкрементальные логи сессии вместе с запросами, но он **выключен**, пока вы сами его не активируете (планы установки `dsh.fish` никогда не включают этот флаг).

Кроме того, плагины теперь могут **регистрировать собственный элемент входа (OAuth или токен) прямо на странице настроек Models**, рядом со встроенными провайдерами.

## Единая входная дверь для Python SDK и ACP

Если вы пользовались браузерным интерфейсом (`dsh web`), вы уже работали через профили. В `v0.1.2-alpha.1` **через ту же самую дверь стали проходить Python SDK и ACP**:

- **Python SDK** теперь запускает сессии через `dsh` Profile и получил готовый артефакт среды выполнения для **Windows x64**.
- **ACP (Agent Client Protocol)** перестал быть частичной заглушкой: управление сессиями, настройки моделей, подключение MCP, права и отмена операций теперь реализованы полностью.

## Четыре несовместимых изменения, которые стоит проверить перед обновлением

В этом пре-релизе были удалены сразу несколько устаревших механизмов. Перед переводом профилей и скриптов на новую версию проверьте четыре пункта:

| Старое допущение до `v0.1.2-alpha.1` | Как работает теперь | Что нужно исправить |
| --- | --- | --- |
| Плагин импортирует `ApiProxy` | **Не загрузится.** Переход на шлюз `@Remote` завершён. | Замените обращения к `ApiProxy` на вызовы `@Remote`. |
| В пресетах или README указан **Code Mode** | Режим переименован в **PTC mode** (`run_code`). Старые логи сессий продолжают читаться. | Обновите название режима в конфигурациях и документации на PTC mode. |
| Публичный `WebFetch` запрашивает подтверждение на каждый URL | Публичный `WebFetch` **включён по умолчанию** (с защитой от SSRF) без запросов на каждый вызов. | Не полагайтесь на окно подтверждения как на барьер для публичных HTTP-запросов. |
| Доступ к `dsh web` по сети без токена | Сетевой доступ к Web UI требует **одноразовый токен** в стартовой ссылке. | Локальный `127.0.0.1` не изменился; для доступа по сети используйте полный URL с токеном из консоли. |

## Улучшения интерфейса, хранения и обновлённое Safety Notice

Помимо архитектурных изменений, заметно удобнее стала повседневная работа:

- **Компактный чат и экономное хранение:** завершённые ответы по умолчанию сворачивают детали процесса и системный промпт, показывают разворачиваемую сводку по токенам и позволяют менять ширину колонки мышью. Записи сессий занимают меньше места на диске, а оборванные хвосты логов автоматически восстанавливаются с понятным предупреждением.
- **Стабильность постоянных оболочек:** исправлены ранний старт PowerShell на macOS/Linux, пустой вывод Bash в середине конвейера на Linux и подвисания macOS при лавинообразном порождении процессов в Bash.

И наконец, обратите внимание на обновлённое **Safety Notice (предупреждение о безопасности)**: в официальном тексте прямо сказано, что DeepSeek Harness **не проходил аудит безопасности**, а песочница, подтверждения и разрешения **не гарантируют полной изоляции**. Включение публичного `WebFetch` по умолчанию — это шаг навстречу удобству, а не признак ужесточения песочницы. Храните секреты вне рабочей папки и относитесь к режиму `danger-full-access` со всей осторожностью.

Полный список изменений: [dsh-v0.1.2-alpha.1](https://github.com/deepseek-ai/deepseek-harness/compare/dsh-v0.1.1-rc.2...dsh-v0.1.2-alpha.1).
