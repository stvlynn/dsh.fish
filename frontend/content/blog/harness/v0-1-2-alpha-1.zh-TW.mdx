設想這樣一個場景：你把 DeepSeek Harness 升級到了 [v0.1.2-alpha.1](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.2-alpha.1)（發佈於 2026 年 8 月 27 日，Git 標籤為 `dsh-v0.1.2-alpha.1`），像往常一樣執行自動化腳本，結果終端機畫面一片空白。十秒過去了，二十秒過去了，正當以為行程卡死準備按 `Ctrl+C` 時，完整的最終回答突然一次性印了出來。

行程並沒有卡死。相反地，`dsh-v0.1.2-alpha.1` 首次在**給人看的進度日誌**與**給機器讀的結果輸出**之間畫下了一條乾淨的分界線。這也是本次預發佈版四大結構性演進之一：從工作階段如何啟動、子智慧體（Subagent）如何選模型，到請求標頭裡攜帶哪些外掛資訊，都在這一版完成了定型。

如果你平時使用 `npx @deepseek-ai/dsh web` 或為目錄開發外掛，不妨跟著我們從終端機表現一路追查到底層協定。

## 為什麼腳本突然「安靜」了：`stderr` 與 `stdout` 的徹底分流

先從剛才那個「終端機空白」的現象說起，因為它解決了一個長期困擾自動化開發者的痛點。

在早期版本中，無頭模式（Headless）會把所有內容混在標準輸出（`stdout`）裡印出：工具呼叫軌跡、中間思考進度、以及最終答案全擠在一條流裡。如果你想把 `dsh` 的輸出透過管線傳給 `jq`，就不得不先寫一堆脆弱的正規表示式去過濾中間日誌。

從 `dsh-v0.1.2-alpha.1` 開始，無頭執行將兩條輸出流徹底分開：

- **`stderr`（標準錯誤流，檔案描述元 2）** 即時輸出執行進度與工具呼叫軌跡。
- **`stdout`（標準輸出流，檔案描述元 1）** 在任務完成前保持絕對安靜，最後**只印出最終結果**。

這意味著你現在可以用一行標準重新導向，同時拿到乾淨的機器結果與即時進度日誌：

```bash
dsh --profile <profile-name> run "your task" >result.txt 2>progress.log
```

## 子智慧體終於不必「被迫繼承」昂貴的父模型

解決了輸出解析問題後，多步任務裡的下一個瓶頸往往是成本與延遲。

在此之前，當主智慧體派生一個子智慧體（比如去翻閱某個子目錄或彙整測試日誌）時，子智慧體預設直接複製父工作階段的模型槽位。如果你的主工作階段正在跑高強度的重型推理模型，哪怕是打雜的小任務也會按最高規格消耗 Token 與等待時間。

在 `v0.1.2-alpha.1` 中，子智慧體獲得了獨立的模型選擇權：

1. **在父級授權範圍內按需選型：** 主智慧體可以在自己已獲授權的供應商與金鑰範圍內，為子智慧體指定不同的供應商、模型與推理強度（reasoning effort）。
2. **啟動時設定輸出上限：** 呼叫方在派生子智慧體時，可以直接指定供應商、模型、推理強度以及**最大輸出長度（maximum output length）**。
3. **Claude Code 與 Codex 子智慧體支援固定模型：** 如果你在 Profile 中掛載了 Claude Code 或 Codex 作為子智慧體，它們現在會讀取各自設定的專屬模型，而不再盲目繼承父工作階段模型。

對於 `dsh.fish` 上的設定作者來說，這意味著你可以在同一個 Profile 裡實現「主模型深度規劃 + 輕量 Flash 子模型並行執行」的高效組合。

## 當外掛啟用時，哪些資訊會隨請求發出？

當你把目錄裡的擴充包（Bundle）安裝進 Profile 後，模型服務商知道你載入了哪些外掛嗎？

從 `dsh-v0.1.2-alpha.1` 起，在使用**官方 DeepSeek 介面卡**時，發出的 API 請求預設會附帶目前 Profile 中**所有已啟用外掛的套件名與版本號**。

這裡有兩個關鍵的邊界設計：

- **外掛標識標頭預設開啟，但允許關閉。** 私有化或注重邊界的部署環境可以在設定中關閉該請求標頭。
- **增量工作階段日誌上傳預設關閉（Opt-in）。** 同一通道還支援隨請求串流上傳增量工作階段日誌，但預設保持**關閉**，除非你明確開啟（`dsh.fish` 產生的安裝計畫絕不會開啟此開關）。

此外，外掛作者還獲得了一個實用的介面擴充點：外掛現在可以**在「設定 → 模型（Models）」頁面直接註冊自訂的登入控制項**，把自己的 OAuth 或 Token 登入卡片與內建供應商並排展示。

## Python SDK 與 ACP 走入同一扇大門

如果你只用瀏覽器介面（`dsh web`），你其實已經在用 Profile 了。`v0.1.2-alpha.1` 的重要變化在於，**所有其他呼叫方式也全部統一到了 Profile 體系下**：

- **Python SDK** 現在同樣透過 `dsh` Profile 啟動，並且本版本新增了 **Windows x64** 預編譯執行期套件（wheel）。
- **ACP（Agent Client Protocol）** 不再是半成品程式碼：工作階段控制、模型設定、MCP 掛載、權限審批和取消操作已全部補齊。如果你之前因為缺少某個控制介面而擱置了 ACP 整合，現在正是重新聯調的節點。

## 升級前必查的四項不相容變更

由於本版本一次性清理了多處舊介面，在遷移舊 Profile 或腳本前，請務必核對以下四項假設：

| `v0.1.2-alpha.1` 之前的舊假設 | 現在的實際行為 | 遷移與修復方式 |
| --- | --- | --- |
| 外掛程式碼仍然匯入 `ApiProxy` | **無法載入。** 已全面遷移至 `@Remote` 閘道。 | 將所有 `ApiProxy` 呼叫替換為 `@Remote` 閘道介面。 |
| 預設或文件仍使用 **Code Mode** 名稱 | 正式更名為 **PTC mode**（`run_code`），舊工作階段歷史仍可正常讀取。 | 將設定與 README 中的 Code Mode 統一更新為 PTC mode。 |
| 公網 `WebFetch` 每次都彈窗請求批准 | 公網 URL 取得**預設開啟**（內建 SSRF 防護），不再逐次彈窗。 | 不要再把審批彈窗當作公網 HTTP 請求的攔截閥門。 |
| 跨區域網路直接裸連 `dsh web` | 透過網路存取 Web UI 必須在啟動連結中攜帶**一次性權杖（one-time token）**。 | 本機迴路（`127.0.0.1`）不受影響；跨機器存取請使用終端機印出的帶權杖完整 URL。 |

## 介面體驗打磨與安全聲明（Safety Notice）更新

除了底層協定演進，日常使用體驗也有不少紮實的改進：

- **更清爽的工作階段介面與更省空間的日誌：** 每條已完成的回答預設折疊中間過程細節與 System 提示詞，回答末尾提供可展開的 Token 統計，並支援拖曳調整對話欄寬。磁碟上的工作階段記錄體積更小，遇到截斷的日誌尾部時會自動修復並指明對應的工作階段。
- **跨平台持久終端機修復：** 修復了 macOS/Linux 上持久 PowerShell 過早啟動、Linux 上持久 Bash 在管線中途傳回空輸出、以及 macOS 在 Bash 瞬間派生大量子行程時卡死的問題。

最後，請留意本版本更新的 **Safety Notice（安全聲明）**：官方明確寫道，DeepSeek Harness **尚未經過安全稽核**，沙箱、審批與權限機制**不保證絕對隔離**。公網 `WebFetch` 預設開啟只是為了減少重複點擊，絕不代表沙箱邊界變得堅不可摧。請繼續將敏感憑證保存在工作區之外，並謹慎對待 `danger-full-access`。

完整變更對比：[dsh-v0.1.2-alpha.1](https://github.com/deepseek-ai/deepseek-harness/compare/dsh-v0.1.1-rc.2...dsh-v0.1.2-alpha.1)。
