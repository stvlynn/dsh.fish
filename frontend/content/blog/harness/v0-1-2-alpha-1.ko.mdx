이런 상황을 떠올려 보세요. DeepSeek Harness를 [v0.1.2-alpha.1](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.2-alpha.1)(2026년 8월 27일 배포, Git 태그 `dsh-v0.1.2-alpha.1`)로 업데이트한 뒤 평소 쓰던 헤드리스 자동화 스크립트를 실행했는데, 터미널에 아무 글자도 찍히지 않습니다. 10초, 20초가 지나고 "프로세스가 멈췄나?" 싶어 `Ctrl+C`를 누르려는 순간, 완성된 최종 답변이 한꺼번에 출력됩니다.

먹통이 된 것이 아닙니다. `dsh-v0.1.2-alpha.1`부터 **사람이 보는 진행 로그**와 **기계가 파싱하는 최종 출력**이 깔끔하게 분리되었기 때문입니다. 이번 프리릴리스에서는 세션이 시작되는 방식, 서브에이전트가 모델을 고르는 방식, 그리고 API 요청에 실리는 플러그인 정보까지 네 가지 핵심 경계가 한꺼번에 재정비되었습니다.

평소 `npx @deepseek-ai/dsh web`을 실행하는 사용자부터 플러그인 제작자까지, 터미널 화면에서 시작해 네트워크 요청 내부까지 차례대로 살펴보겠습니다.

## 스크립트가 갑자기 조용해진 이유: `stderr`와 `stdout`의 분리

방금 이야기한 '빈 터미널' 현상부터 짚어 보겠습니다. 자동화 스크립트를 짜 본 개발자라면 누구나 겪었을 불편함을 해결한 변경입니다.

이전 빌드에서는 헤드리스 모드를 실행하면 도구 호출 내역, 중간 진행 상태, 최종 답변이 모두 표준 출력(`stdout`) 하나에 뒤섞여 나왔습니다. 결과를 `jq`로 넘기거나 파일로 저장하려면 정규표현식으로 중간 로그를 먼저 걸러내야 했습니다.

`dsh-v0.1.2-alpha.1`부터는 두 스트림이 명확히 나뉩니다.

- **`stderr`(표준 에러, 파일 디스크립터 2)**는 에이전트가 작업하는 동안 진행 상황과 도구 트레이스를 실시간으로 흘려보냅니다.
- **`stdout`(표준 출력, 파일 디스크립터 1)**은 턴이 끝날 때까지 아무것도 찍지 않다가 마지막에 **최종 결과만** 출력합니다.

덕분에 이제는 기본 리다이렉션 한 줄만으로 깔끔한 결과 파일과 실시간 진행 로그를 동시에 얻을 수 있습니다.

```bash
dsh --profile <profile-name> run "your task" >result.txt 2>progress.log
```

## 서브에이전트가 부모의 무거운 모델을 그대로 물려받지 않아도 됩니다

출력 스트림을 정리하고 나면, 다단계 작업에서 눈에 띄는 다음 병목은 비용과 응답 속도입니다.

이전에는 메인 에이전트가 보조 서브에이전트(예: 폴더 검색이나 테스트 로그 요약)를 띄우면 무조건 부모 세션의 모델을 그대로 물려받았습니다. 부모 세션이 무거운 추론 모델을 쓰고 있으면 간단한 보조 작업까지 똑같이 높은 비용과 대기 시간을 치러야 했습니다.

`v0.1.2-alpha.1`에서는 부모 세션이 가진 권한 범위 안에서 서브에이전트마다 알맞은 모델을 따로 지정할 수 있습니다.

1. **서브에이전트별 맞춤 모델 선택:** 부모 에이전트는 자신이 이미 인가받은 제공자와 키 범위 안에서 서브에이전트의 제공자, 모델, 추론 강도(reasoning effort)를 선택할 수 있습니다.
2. **생성 시점 출력 길이 제한:** 서브에이전트를 호출할 때 모델과 추론 강도는 물론 **최대 출력 길이(maximum output length)**까지 지정할 수 있습니다.
3. **Claude Code 및 Codex 서브에이전트 전용 모델 지정:** Claude Code나 Codex를 서브에이전트 번들로 사용하는 경우, 부모 모델을 따라가는 대신 프로필에 지정된 전용 모델을 사용합니다.

`dsh.fish`의 프로필 작성자 입장에서는 "부모는 깊은 추론 모델, 서브에이전트는 빠른 Flash 모델"이라는 구성을 하나의 프로필 안에 명확히 정의할 수 있게 된 셈입니다.

## 플러그인을 켜면 어떤 정보가 네트워크를 타고 나갈까요?

카탈로그에서 Bundle을 설치하고 활성화하면 모델 제공자는 어떤 플러그인이 켜져 있는지 알 수 있을까요?

`dsh-v0.1.2-alpha.1`부터 **공식 DeepSeek 어댑터**를 사용할 때 외부로 나가는 API 요청에는 **활성화된 모든 플러그인의 패키지 이름과 버전**이 메타데이터 헤더로 포함됩니다.

여기서 알아 두어야 할 두 가지 기준이 있습니다.

- **플러그인 식별 헤더는 기본 켜짐이지만 끌 수 있습니다.** 배포 환경의 정책에 따라 헤더 전송을 비활성화할 수 있습니다.
- **세션 로그 증분 업로드는 명시적 선택(Opt-in)입니다.** 같은 요청 경로를 통해 세션 로그를 실시간 업로드하는 채널도 추가되었지만 기본값은 **꺼짐**이며, 사용자가 직접 켜야만 작동합니다(`dsh.fish`의 설치 계획은 이 플래그를 절대 켜지 않습니다).

또한 플러그인 제작자를 위해 **Models 설정 페이지에 자체 로그인 컨트롤(OAuth 또는 토큰 로그인)을 등록할 수 있는 훅**이 새롭게 추가되었습니다.

## Python SDK와 ACP도 이제 같은 Profile 정문을 통과합니다

브라우저 UI(`dsh web`)만 쓰던 분들에게는 이미 익숙한 Profile이 이제 **Python SDK와 ACP를 포함한 모든 실행 경로의 유일한 정문**이 되었습니다.

- **Python SDK** 런타임에 **Windows x64** 사전 빌드 아티팩트가 추가되었습니다.
- **ACP(Agent Client Protocol)**가 스텁 수준을 벗어나 세션 제어, 모델 설정, MCP, 권한 요청, 작업 취소까지 표준 제어 항목을 모두 갖추었습니다.

## 업그레이드 전에 꼭 확인해야 할 4가지 호환성 체크리스트

이번 버전에서는 레거시 경로 여러 개가 한꺼번에 제거되었습니다. 기존 프로필이나 자동화 스크립트를 옮기기 전에 아래 네 가지를 먼저 점검하세요.

| `v0.1.2-alpha.1` 이전의 가정 | 변경된 실제 동작 | 마이그레이션 방법 |
| --- | --- | --- |
| 플러그인에서 `ApiProxy`를 임포트함 | **로드 실패.** `@Remote` 게이트웨이로의 전환이 완료되었습니다. | `ApiProxy` 호출을 `@Remote` 게이트웨이 인터페이스로 교체하세요. |
| 프리셋이나 문서에서 **Code Mode**라는 이름을 씀 | 런타임 명칭이 **PTC mode**(`run_code`)로 변경되었습니다(기존 세션 기록은 읽기 가능). | 프리셋과 README의 Code Mode 표기를 PTC mode로 업데이트하세요. |
| 공개 URL `WebFetch`가 매번 승인 창을 띄움 | 공개 네트워크 `WebFetch`가 **기본 켜짐**(SSRF 보호 내장)으로 바뀌었습니다. | 공개 URL 요청을 막는 용도로 승인 프롬프트에 의존하지 마세요. |
| 네트워크로 노출된 `dsh web`에 토큰 없이 접속함 | 외부 네트워크에서 Web UI에 접근할 때 **시작 URL의 일회용 토큰**이 필수입니다. | 로컬 루프백(`127.0.0.1`)은 그대로지만, 원격 접속 시에는 토큰이 포함된 전체 URL을 사용하세요. |

## 세션 UI·스토리지 개선 및 Safety Notice(안전 고지)

일상적인 사용성과 안정성도 함께 다듬어졌습니다.

- **더 가벼워진 대화 화면과 디스크 저장소:** 답변이 완료되면 중간 과정과 System 프롬프트가 기본으로 접히고, 답변 끝에 펼칠 수 있는 토큰 사용량이 표시되며, 대화 열 너비를 마우스로 조절할 수 있습니다. 디스크의 대화 기록 용량도 줄어들었고 잘린 로그 꼬리는 세션 이름과 함께 경고를 띄우며 복구됩니다.
- **운영체제별 영구 셸 안정화:** macOS/Linux에서 영구 PowerShell이 너무 일찍 시작되던 문제, Linux 영구 Bash가 파이프라인 도중 빈 출력을 내던 문제, macOS에서 Bash가 수많은 프로세스를 순간 생성할 때 멈추던 문제가 해결되었습니다.

마지막으로 이번 태그에서 업데이트된 **Safety Notice**를 꼭 기억해 두세요. DeepSeek Harness는 **보안 감사를 받지 않았으며**, 샌드박스와 승인 및 권한 체계가 **완벽한 격리를 보장하지 않는다**는 문구가 공식 문서에 명시되었습니다. 공개 `WebFetch`가 기본 켜짐으로 바뀐 것은 편의성 개선일 뿐 샌드박스가 더 단단해졌다는 뜻이 아닙니다. 민감한 자격 증명은 워크스페이스 밖에 두고 `danger-full-access`는 이름 그대로 신중하게 다루어야 합니다.
